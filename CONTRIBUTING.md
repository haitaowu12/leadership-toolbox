# Contributing

Open an issue or draft PR for a concrete leadership job, a source correction or a demonstrated usability problem. Include the affected method ID/version, the proposed change, a public source, evidence limits and a fictional or properly consented anonymised example. Never include identifying workplace or personal details.

Use the [method template](skills/leadership-toolbox/templates/method-card.md). Describe prerequisites, failure/stop conditions, an observable output and a modest outcome signal. Do not introduce global scores, personality diagnoses or success probabilities. New IDs represent distinct jobs; preserve retired IDs and document redirects rather than reusing them.

Before review: check licence/reuse terms, all links, the release allowlist, relevant tests and the changelog. Separate author examples from unseen model evaluations and human field evidence. If a schema changes, implement and test a lossless migration or fail without changing data; document rollback and keep unknown fields. Owner approval is required to merge and release substantive changes.

## Expand for a distinct need

Add a method only when its required output or mechanism fills a real gap; do not pad the count with branded synonyms. Preserve existing IDs. Update both readable and structured catalogs, profile dimensions, card sources/licence, metric contract, related links, release allowlist and tests. Explain what makes the addition different from the nearest existing card and include a counterexample.

Use context anchors as editorial judgments with unknowns and user corrections. Do not add universal leadership ratings, fixed person types, summed fit scores or success probabilities. Keep independent model executions distinct from author examples and record exact tested revision, model/settings if available, full prompt/output, evaluation criteria and limits. Do not fabricate missing provenance.

## Deepen knowledge rather than pad citations

For a new source, add a stable E/B/P record in the [source library](skills/leadership-toolbox/references/sources.json) with authors, publication year/version, DOI when available, verified URL, source role, actual access and inspected sections, topic/method links, claim limit and reuse boundary. Full-text availability is not proof of whole-book reading. Abstract-only evidence must be labeled; metadata-only records cannot support empirical claims. Look for corrections, contradictory/null findings, measurement limitations, bundled interventions, and population/context transfer.

Update the [knowledge topics](skills/leadership-toolbox/references/knowledge/README.md), [method evidence map](skills/leadership-toolbox/references/evidence-map.json), card and structured metric contract where the finding changes practice. Preserve descriptive origins and explicit gaps. Do not repackage protected books/articles, assets or assessment instruments; independent explanation and citation do not grant source rights. Check the current asset-specific terms before any licensed reuse. A company's method page may be appropriate provenance, but it should not impersonate independent efficacy evidence.
