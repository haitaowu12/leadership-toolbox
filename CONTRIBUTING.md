# Contributing

Open an issue or draft PR for a concrete leadership job, a source correction or a demonstrated usability problem. Include the affected method ID/version, the proposed change, a public source, evidence limits and a fictional or properly consented anonymised example. Never include identifying workplace or personal details.

Use the [method template](skills/leadership-toolbox/templates/method-card.md). Describe prerequisites, failure/stop conditions, an observable output and a modest outcome signal. Do not introduce global scores, personality diagnoses or success probabilities. New IDs represent distinct jobs; preserve retired IDs and document redirects rather than reusing them.

Before review: check licence/reuse terms, all links, the release allowlist, relevant tests and the changelog. Separate author examples from unseen model evaluations and human field evidence. If a schema changes, implement and test a lossless migration or fail without changing data; document rollback and keep unknown fields. Owner approval is required to merge and release substantive changes.
